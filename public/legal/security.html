Security Architecture & Policy

Last Updated: September 27, 2026 • Version: 1.0 (Datathon Edition)
Important Hackathon Notice: These documents are provided for this hackathon/demo project (IBM Z Datathon 2026) and should be reviewed by a qualified legal professional before being used as production legal terms. Z-Sentinel AI is an educational demonstration prototype and has not undergone formal commercial third-party security audits.

1. Defense-in-Depth Architecture

Z-Sentinel AI implements a layered, zero-trust security paradigm specifically designed to demonstrate resilient cyber defense for high-throughput mainframe streams:

Firebase Google Authentication
  ↓
Protected Frontend Routes (Client-Side Auth Guard)
  ↓
FastAPI Backend (CORS & Strict Pydantic Schema Validation)
  ↓
Privacy Guardian Engine (Local Regex & Deterministic Masking)
  ↓
Deterministic Heuristic Rule Engine (Explainable Deductions)
  ↓
Unsupervised Machine Learning (Isolation Forest Anomaly Scoring)
  ↓
Composite Risk Scoring (0–100 Classification: Low, Medium, High, Critical)
  ↓
Local Explanation Engine (Optional Backend-Only Groq AI Fallback)

2. Key Security Safeguards

  • Zero Client-Side Secrets: Groq API keys, server tokens, and private credentials reside strictly in server-side environment variables (.env). No private keys are ever embedded in HTML, JavaScript, or public repositories.
  • Isolated Judge Demo Environment: The Judge Demo mode operates inside a sandboxed state using exclusively deterministic synthetic records. It does not access real user accounts, private databases, or production credentials.
  • Local Fallback Resilience: Unlike cloud-dependent AI tools, the core security engine does not crash if external AI APIs fail or time out. Deterministic algorithms ensure uninterrupted risk evaluation.
  • Strict Data Minimization: Raw account numbers (PAN), government identifiers (SSN), emails, and phone numbers are redacted on-premise prior to database persistence or LLM explanation queries.
  • Immutable Audit Logging: Security interventions (such as automated wire freezes, PII redactions, and analyst queries) are recorded in an audit trail with timestamps, severity levels, and provenance tags.

3. Responsible Vulnerability Disclosure

We welcome responsible reporting of vulnerabilities discovered in our codebase. If you identify a potential security issue, please notify the development team via our Contact Page. Please allow reasonable time for remediation prior to public disclosure.
